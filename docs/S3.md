# S3 hosts (AWS, Wasabi, and S3-compatible)

CloudMount uses rclone’s **s3** backend. You add an S3 **host**, then create **mounts** (buckets or prefixes) as usual. Browse remote lists top-level entries (for AWS: buckets you can list).

## Auth modes

| Mode | When to use | What you enter |
|------|-------------|----------------|
| **Static access key + secret** | Wasabi, MinIO, IAM user long-lived keys | Provider, region/endpoint as needed, access key, secret (stored in Keychain / Credential Manager) |
| **AWS profile** | Real AWS via `~/.aws` | Provider **AWS**, region, **profile name** from `~/.aws/config` / `credentials` |

Profile mode covers:

- Long-lived keys already in a named profile  
- **AWS SSO / IAM Identity Center** (after `aws sso login`)  
- **IAM Roles Anywhere** (or other tools) when the profile uses `credential_process`  

CloudMount does **not** implement SSO or Roles Anywhere itself; it uses the profile the AWS CLI / SDK would use.

### Setup (profile)

1. Configure the profile outside CloudMount, e.g. `aws configure sso` or edit `~/.aws/config`.  
2. Hosts → **Add host** → type **s3**.  
3. **Auth mode:** AWS profile (`~/.aws`).  
4. Pick or type the **profile** (e.g. `loopora`).  
5. Set **region** (and leave endpoint empty for AWS).  
6. **Save** → **Test** (should list buckets if `s3:ListAllMyBuckets` is allowed).  
7. **Browse remote** or **Add mount** with a bucket/prefix path.

Optional: **AWS login** on the host row runs `aws sso login --profile …` manually.

### Setup (static keys)

1. Auth mode: **Static access key + secret**.  
2. Provider (e.g. **Wasabi** or **AWS**), endpoint/region as required.  
3. Access key + secret → Keychain / Credential Manager.  
4. Test / browse / mount as above.

SSE, KMS, object lock, and similar options are **not** required in the host form. If your identity can use the bucket (and KMS key when needed), rclone handles encryption automatically.

## Expired credentials (SSO)

CloudMount does **not** proactively refresh tokens on every browse or background poll.

When **Test**, **Browse**, or **Mount** fails with an **auth/expiry** error for a profile host:

1. CloudMount runs **`aws sso login --profile <name>`** once (may open a browser).  
2. Retries the operation once.  

IAM **permission** errors (e.g. cannot list buckets) are **not** treated as login failures — you get a clear message instead.

Requires [AWS CLI v2](https://aws.amazon.com/cli/) on `PATH` for SSO login.

## Permissions

| Operation | Typical need |
|-----------|----------------|
| Browse root / Test | `s3:ListAllMyBuckets` (or you’ll only be able to open known bucket paths) |
| Browse inside a bucket | `s3:ListBucket` on that bucket |
| Mount read/write | Read/write object APIs as required by your workload |

If list-all-buckets is denied, type a bucket name as the remote path or open that path in Browse if you know it.

## Mounts

Same as any other host: empty remote path = root (all listable buckets for AWS), or `bucket` / `bucket/prefix`. Prefer **NFS** or **FUSE** on macOS per [MOUNT_MODES.md](./MOUNT_MODES.md); on Windows use WinFsp mount.
